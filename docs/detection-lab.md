# 定位检测靶场（DetectionLab）

一个只做检测、不改定位的 App。用来观察「系统级定位模拟」会在哪些特征上留下痕迹，
是反作弊机制的研究与验证工具。

## 它检测什么

分两类规则，共 10 条。

### 坐标特征

| 规则 | 级别 | 依据 |
|---|---|---|
| 系统标记该坐标由软件模拟 | 高风险 | `CLLocation.sourceInformation.isSimulatedBySoftware`（iOS 15+） |
| 坐标由外部配件提供 | 可疑 | `sourceInformation.isProducedByAccessory` |
| 坐标长时间完全静止 | 高风险 | 多次采样后小数点 6 位完全相同；真实 GPS 必然抖动 |
| 精度与海拔符合模拟器默认值 | 可疑 | 水平精度恰好 5 米、海拔恰好 0 米 |
| 坐标时区与设备时区不符 | 可疑 / 高风险 | 经度推算时区与 `TimeZone.current` 相差 4 / 6 小时以上 |
| 定位时间戳偏旧 | 提示 | 最新样本超过 10 秒 |

### 进程环境

| 规则 | 级别 | 依据 |
|---|---|---|
| 检测到注入库 | 高风险 | dyld 镜像路径含 `/var/jb`、substrate、ellekit、frida 等 |
| 环境变量注入了动态库 | 高风险 | `DYLD_INSERT_LIBRARIES` 非空 |
| 进程正被调试器附加 | 可疑 | sysctl 读到 `P_TRACED` |
| 存在越狱环境痕迹 | 可疑 | `/var/jb/bin/sh` 等路径存在 |
| 本 App 自身持有定位模拟权限 | 高风险 | `com.apple.locationd.simulation` |

## 关键设计

**检测逻辑与平台解耦。** 判定规则 `TamperDetector` 是纯函数，输入是
`LocationSample` 与 `InjectionEnvironment` 两个普通结构体，不依赖 CoreLocation。
所以 23 项规则测试能在没有 iOS SDK 的机器上跑：

```bash
bash tools/detection-tests/run.sh
```

真机采集部分在 `EnvironmentProbe`，只负责把系统数据填进这两个结构体。

**靶场不申请模拟权限。** 它要模拟「一个普通 App」的视角，拿到
`locationd.simulation` 就失去检测意义了。

## 使用

1. 从 Release 下载 `DetectionLab.ipa`，用 TrollStore 安装
2. 打开 App，允许定位权限
3. 用定位模拟工具（如「寻定位」）把位置改到别处
4. 回到靶场，看检测结论

## 预期结果

用「寻定位」模拟后，靶场通常会命中：

- **坐标长时间完全静止**：模拟器给的是固定值，不抖动
- **精度与海拔符合模拟器默认值**：寻定位填的是 5 米精度、0 米海拔
- 模拟到境外时，还会命中**时区不符**

这正好解释了为什么系统级模拟会被风控识别：它改的是环境事实，
但「这个事实是模拟出来的」这个标记由系统自己维护，App 读得到。

## 对比：进程内注入为什么不同

`zjq1.0.deb` 这类插件注入到目标 App 进程内，能直接改写目标 App 的检测函数返回值。
检测代码执行时看到的就是「干净」的结果——不是伪装得好，而是判断本身被改写了。

**这才是本质差异**：系统级模拟留下可检测的痕迹，进程内注入不留。
代价是进程内注入需要越狱环境，且要针对每个目标 App 单独适配。

## 扩展

想加规则，只改 `TamperDetector.swift` 并在 `tools/detection-tests/main.swift`
补测试用例即可，不需要动 iOS 代码。

几个值得补的方向：

- **基站与 WiFi 交叉验证**：模拟坐标配不上周围真实基站，这是最强的信号
- **加速度计与陀螺仪**：人移动时传感器有数据，模拟时完全静止
- **速度与位移一致性**：两个时间点的位移与 `speed` 字段是否对得上
