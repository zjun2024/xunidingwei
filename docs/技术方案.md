# 手机端 iPA 虚拟定位技术方案

把 Windows 版 `ios_loc.py` 的定位能力搬到 iPhone 本机，做成可以直接用
TrollStore（巨魔）安装的 iPA。

---

## 1. 为什么不能照搬 Windows 版的做法

Windows 版走的是这条链路：

```
电脑 Python → pymobiledevice3 → USB(usbmuxd) → lockdownd → com.apple.dt.simulatelocation
```

这条路的前提是**一台外部主机**。手机内部没有 USB 回环，App 无法以「USB 主机」
身份连到自己，所以 `usbmuxd + lockdownd + DVT` 这套协议在手机端根本走不通。
把它硬塞进 iPA，只会得到「连不上设备」。

Windows 版真正起作用的只有最后一步：让 **locationd** 接受一条虚拟坐标。
手机端要做的是**换一条能到达 locationd 的通道**。

## 2. 手机端的正确通道

iOS 里有一个只在开发/测试场景使用的私有组件：

```objc
@interface CLSimulationManager : NSObject
@property (assign) uint8_t locationDeliveryBehavior;
@property (assign) uint8_t locationRepeatBehavior;
- (void)clearSimulatedLocations;
- (void)appendSimulatedLocation:(CLLocation *)location;
- (void)flush;
- (void)startLocationSimulation;
- (void)stopLocationSimulation;
@end
```

它位于 CoreLocation，内部通过 XPC 直连 `locationd`，也就是 Xcode
「Simulate Location」用的同一个入口。因此手机端方案是：

```
App 进程 → CLSimulationManager → XPC → locationd → 全系统定位被替换
```

和 Windows 版的区别只有通道，效果完全等价：系统级、全 App 生效、可随时恢复。

### 必需的权限

`locationd` 会校验调用方签名里的 entitlement：

```xml
<key>com.apple.locationd.simulation</key>
<true/>
```

这条权限不在公开的开发者权限清单里，正常签名拿不到。TrollStore 的做法是
**保留 iPA 里已有的 ad-hoc 签名**，所以只要打包时用 `ldid -S` 把这份
entitlements 签进主二进制，安装后权限就生效。

> 关键点：必须安装本仓库产出的 iPA。用爱思、AltStore、自签工具重新签名会
> 丢掉这条权限，App 能装能开，但定位不生效。

## 3. 整体架构

```
ios-app/
├── project.yml                     # xcodegen 工程描述
├── build_ipa.sh                    # 编译 → ldid 注入权限 → 打 Payload
└── Xunidingwei/
    ├── XunidingweiApp.swift        # 入口
    ├── Models.swift                # 地点模型 + 输入解析（对齐 ios_loc.py）
    ├── Generated/LocationData.swift# 由 tools/gen_locations.py 生成
    ├── Engine/
    │   ├── LocSimEngine.swift      # CLSimulationManager 封装（运行时反射）
    │   ├── KeepAlive.swift         # 无声音频后台保活
    │   └── LocSimStore.swift       # 状态、历史、自检
    ├── Views/
    │   ├── ContentView.swift       # 主界面
    │   ├── CatalogView.swift       # 国家/城市浏览与搜索
    │   └── DiagnosticsView.swift   # 环境自检
    └── Xunidingwei.entitlements    # locationd.simulation 等权限
```

### 为什么用运行时反射调用

`CLSimulationManager` 没有公开头文件。如果直接写 `CLSimulationManager()`，
编译期会因为找不到符号而失败。所以用 `NSClassFromString` + `perform(_:)`
在运行时绑定，同时对每个 selector 做 `responds(to:)` 检查，缺失时给出中文提示
而不是崩溃。

## 4. 输入解析：与 Windows 版保持完全一致

`windows/ios_loc.py` 里的 `DATA` 表是唯一数据源。`tools/gen_locations.py`
把它生成成 `LocationData.swift`，`Models.swift` 按同样的三条优先级建索引：

1. 国家名 → 该国第一个城市（默认城市）
2. 城市名
3. 国家名 + 城市名

所以下面这些输入在两端行为一致：

| 输入 | 结果 |
| --- | --- |
| `英国` | 英国 伦敦 |
| `洛杉矶` | 美国 洛杉矶 |
| `美国洛杉矶` / `美国 洛杉矶` | 美国 洛杉矶 |
| `uk` / `london` / `nyc` | 对应地点（忽略大小写和空格） |
| `51.5074 -0.1278` | 自定义坐标 |
| `91 0` | 解析失败（纬度越界） |

`tools/test_parity.py` 会断言 Swift 端规则与 Python 端输出一致，改任何一侧
都会被这个测试拦住。

## 5. 后台保活

`CLSimulationManager` 由**本进程**驱动 locationd。App 被挂起或被杀，模拟就中断。
解决方式是在 `Info.plist` 声明 `UIBackgroundModes = audio`，并用
`AVAudioEngine` 循环播放静音缓冲，让进程长期存活。

- 不产生任何声音（缓冲区全是 0）
- `.mixWithOthers` 不会打断用户正在听的音乐
- 界面上的「后台保活」开关可以关掉，关掉后只在 App 前台时保持定位

## 6. 安装步骤

1. 到仓库 Releases 下载 `Xunidingwei.ipa`（或本地运行 `ios-app/build_ipa.sh`）
2. 用 AirDrop / 文件 App / 爱思把 iPA 传到手机
3. 用 TrollStore 打开该文件 → Install
4. 打开 App → 「环境自检」，三项都应打勾
5. 输入国家/城市，或从地点列表里选，即可定位

## 7. 环境要求与排错

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 自检里「定位模拟引擎」不通过 | 系统低于 iOS 15 | 无解，系统没有该组件 |
| 自检里「定位模拟权限」不通过 | iPA 被重新签名 | 重装本仓库的原始 iPA |
| 提示成功但地图没变 | 定位服务关闭 | 设置 → 隐私与安全性 → 定位服务 |
| 提示成功但地图没变（iOS 16+） | 开发者模式未开 | 设置 → 隐私与安全性 → 开发者模式 |
| 锁屏后定位失效 | 保活被关掉或被系统清理 | 打开「后台保活」，重新进入 App |

## 8. 与 Windows 版的分工

| | Windows 版 | 手机端 iPA |
| --- | --- | --- |
| 是否需要电脑 | 需要，全程连着 | 不需要 |
| 通道 | USB → lockdownd → DVT | 进程内 → XPC → locationd |
| 依赖 | Python + pymobiledevice3 | 无 |
| 权限 | 无需特殊权限 | `com.apple.locationd.simulation` |
| 适用 | 任意 iOS 版本 | iOS 15+（巨魔可装的机型） |

Windows 版保留在 `windows/` 目录，仍可继续使用；两端共用同一份地点表。
